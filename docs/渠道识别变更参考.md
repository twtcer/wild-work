## 1. 渠道清单变化：13 → 22 + 自定义渠道框架

`provider.Kind` 是**渠道识别的唯一标识**（`internal/provider/provider.go`），也是模型名前缀
（`channel/<model>` 路由，R10）、账本流水 `UsageEntry.Ch`、统计平台表、前端 `CH_LABEL` 的共同取值。

## 2. 渠道识别/路由的架构变化（新增渠道必须知道的骨架）

### 2.1 登录编排：switch → `loginFlows` 表驱动（H1/H2 修复）

`internal/app/app.go`：**一个渠道一条记录**，登录能力的唯一来源。

```go
loginFlows[provider.X] = &loginFlow{
    Start:    func(c *http.Client, sp string) (string, error) { ... }, // 与 login_* 包签名同构
    Poll:     wrapPoll(loginx.Poll, loginx.ErrPending, completeX),
    Shutdown: loginx.Shutdown,          // 释放本机资源（回调口/浏览器），幂等
    clientFactory: ...,                  // nil = login.NewClient()
    openIncognito: true,                 // 授权页复用浏览器会话的渠道必须无痕
    pollTimeout:   loginx.FlowTTL,       // 回调口存活 > 通用 5m 的渠道必须对齐
    DisplayURL:    "...",                // 只引导不轮询（GLM 形态）
    noFlowReason:  "...",                // 导入型/匿名/两步流程渠道的明确拒绝说明
}
```

**硬约束**（`init()` 有 panic 校验）：每条记录**恰好表达一种发起方式**（Start / DisplayURL / noFlowReason 三选一）。
新增渠道若漏登记，`login_branch_ast_test.go` 会报「未在 loginFlows 里登记 ⇒ 前端 ⟳ 变死按钮」。

**配置注入模式**：需要随登录传入的配置**不得改表函数签名**，走包级变量 + 发起前写入
（`regionForLogin` / `lobsterAICallbackPort` / `callbackOpts` 三个先例；fork 的 R126 回调配置走 `callbackOpts`）。

**取消/收尾统一走 `a.shutdownLoginFlow(kind)`**：不再手写逐渠道 if（Loomy Shutdown 曾被误插进 Raccoon 块，同一坑复发三次）。

**人工回调通道**（异地/局域网取码）：白名单 `manualCallbackKind()` = CodeArts / LobsterAI / TraeWork / QwenWork / Gemini，
**单一来源**——`/api/login/start` 的 `manual_callback` 显隐与 `/api/login/callback` 的接受判定都调它。

### 2.2 模型 ID 单一来源（R52/R59）

`provider.PublicModelID(kind, upstreamID)` / `provider.SplitModelID(model)` —— 对外模型名拼接与解析的**唯一取数点**。
新增渠道不得自己拼 `kind + "/" + id`。

### 2.3 装配三处（main.go，R34 家族清单）

新增渠道的完整接线（漏一处即静默失效）：

1. `server.Runtime{Kind, Pool, Upstream, StaticModels, SingleAccount?, ...}` —— 主链路（对话/模型列表）
2. `app.Runtime{Kind, Pool, Upstream, Scheduler}` —— 面板/签到；别名渠道（TraeCode）设 `Alias: true` 且**无独立 Scheduler**
3. `appRuntimes` / 前端 `CH_LABEL` + `CH_CLASS`（`app.js`，配色见 `docs/渠道配色规范.md` R99）
4. **`go xxxSch.Run(sctx)`**（R34：漏了则自动签到/保活静默不跑，`scheduler_start_test.go` 静态扫描拦截）
5. 定时任务关掉的渠道传 `[]int{}` 而非 `nil`（R39：`nil` 会落默认 09:00/22:00）
6. 流式 client 必须有独立 `StreamHTTP`（R35），`applyProxies` 两处都要把 {HTTP, BillingHTTP?, StreamHTTP} 一起传
7. 自定义渠道额外走 `stats.RegisterChannelKind(name)`（R66）与 `buildCustomRuntimes`

### 2.4 错误分类与惩罚的渠道级差异

| 结构属性 | 语义 | 当前使用者 |
|----------|------|------------|
| `Runtime.SingleAccount` | 跳过**所有**账号级惩罚，错误一律原文透传（不变量 22） | oczen、kilo |
| `NoCooldownOnServerError` | 传输层错误不冷却（被 SingleAccount 涵盖，保留是为不依赖顺序） | oczen、kilo |
| `ErrPassthrough` | 请求级不惩罚，透传原文 | 单账号渠道、地区限制（cline `regionRetryMarkers`） |
| 模型级冷却（`ErrSoftRate` 模型维度） | 上游按模型限流/饱和时不软化整个账号 | workbuddyai 429（R38/R46）、qodercn 排队 |
| `noExplicitCheckin(kind)` | 手动/首次签到跳过（无签到端点的渠道） | workbuddyai、qwenwork、oczen、kilo、zcode、gemini、cline + 全部 custom |
| `creditsNAKind(group)` | 面板积分位显示「不适用」而非 0 | oczen、kilo、cline + 全部 custom |

### 2.5 模型降级链与思考强度（R54/R61/R94、R49/R63）

- `server.Handler.ModelFallbacks` / `ReasoningEfforts` 两份内存副本，面板保存经 `SetModelFallbacks` / `SetReasoningEfforts` 热更新；
  **启动时必须载入**（R61），且 `fbSyncer`/`efSyncer` 推送（R122：改渠道名时必须联动，否则静默失效）。
- 降级三维归因唯一权威定义：`docs/模型降级链定义.md`；硬前提「能换模型的必须能换号」由
  `fallback_dimension_test.go` 锁定。
- 思考档位**只透传上游声明，绝不编造**（R49）；`/v1/models` 输出 `supported_parameters` / `reasoning.mandatory`
  也按已声明能力导出（R124）。

### 2.6 备用上游通道（R57/R62/R64）

旧「每渠道代理」`proxies` 段已删除，一次性迁移进 `backup_proxy`（`migrateLegacyProxies`，config.normalize）。
编排统一在 `internal/backuplink`（`Replay`），cline/oczen 共用；**默认不参与任何请求**，仅按需取用。
新增渠道要接备用通道时走 `backuplink.Replay`，不得自己写重放循环。

### 2.7 自定义渠道（R66）——「动态 Kind」的识别特例

- Kind = 用户填的 `name`（改名走 `renames:[{new,old}]` 级联，R122）；虚拟账号 UID `custom-<name>`；
  state 文件 `state-custom-<name>.json`。
- **无积分概念**：不进积分刷新/明细/签到；`creditsNAKind`/`noExplicitCheckin` 含全部 custom。
- 模型校验 = 静态表 ∪ 动态目录并集（R42 同款 `liveIDs` 单调扩大）。
- 历史流水仍记旧渠道名（不改写历史=不伪造账本）；改名后旧前缀模型立即 400，**不做 Router alias**。

## 4. 新增渠道速查清单（合并后版本）

> 与 AGENTS.md §0.2 / R34 清单一致，此处按本次合并后的实际结构展开：

1. `internal/<channel>/` 实现 `provider.Upstream`（`Stream`/`Aggregate` 的 model **显式传参**，R14）
2. `internal/provider/provider.go` 加 `Kind` 常量
3. `internal/auth` 加 `Load<Channel>Dir()`（glob 前缀边界注意，如 `qoder*.json` 陷阱）
4. `main.go` 装配三处（server.Runtime / app.Runtime / `go xxxSch.Run`，见 2.3）
5. `internal/login_<channel>/` 实现登录（签名与其它包**同构**）→ 登记 `loginFlows`（恰好一种发起方式）
6. 需要异地取码 → 加入 `manualCallbackKind` 白名单 + `SubmitCallbackURL`
7. 前端 `CH_LABEL` / `CH_CLASS`（配色对齐 `docs/渠道配色规范.md`）
8. 错误分类 `Classify`（429 优先于 hardMarkers，不变量 15）；单账号渠道声明 `SingleAccount`
9. 无签到 → `noExplicitCheckin`；无积分 → `creditsNAKind`
10. 补回归测试 + `node scripts/ui-static-check.mjs` 全绿
